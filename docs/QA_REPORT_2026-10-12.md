## 6. Notes & recommendations (not blockers)

1. **Matchmaking scope** — matchmaking is challenge-based (create + share code, or join by code). There is no random quick-match queue; confirm this matches the release product intent.
2. **WiFi ↔ mobile radio switch** — no distinct code path beyond reachability regain (covered by automated tests). Recommend a manual on-device airplane-mode/radio-switch pass before store submission.
3. **DB-down runtime behavior** — an unreachable DB at boot exits the process cleanly (fail-fast). Health endpoint returns 503 during DB outage (integration-tested). A live runtime-outage drill (stop MySQL under traffic) was not run against the shared dev database; consider staging.
4. **Burst registration** — 429 responses under concurrent registration are the anti-abuse throttler working; client surfaces a friendly error. No action needed.
5. **phase3 e2e flake (historical)** — fixed test usernames can collide on a long-lived dev DB (seen once previously; not observed today). Re-run resolves; consider unique suffixes if it recurs.
